# 随身盘（U 盘便携模式）

「随身盘」把本机已安装的 AI CLI 工具连同个人配置复制到 U 盘，插到另一台机器后不需要安装、不需要重新登录，直接运行盘内的启动脚本即可进入同样的工作状态。

当前支持四个工具：OpenCode、Claude Code、Codex CLI、pi。

## 前提

- 要携带的工具已在本机安装并至少成功运行过，配置与登录状态已经存在。
- 目标 U 盘可写，剩余空间大于所选工具的总体积（四个全选约 1.2 GB，含会话历史会显著增加）。
- 写入前退出正在运行的同名工具。运行中复制配置文件可能得到半写状态，会话数据库尤其明显。

## 操作步骤

1. 插入 U 盘，打开侧栏「随身盘」面板。面板每次进入都会重新枚举盘符和工具。
2. 在磁盘列表中选择目标盘。列表包含可移动盘和通过 USB 接口接入的固定盘（U 盘形态的固态硬盘也能识别）。
3. 勾选要携带的工具，面板显示每个工具的预估体积与来源状态。
4. 按需调整两个开关，见下文。
5. 点「写入 U 盘」，等待进度完成。写入结束后面板会回读盘内结果，显示每个工具的文件数与实际体积。

写入只发生在 `<盘根>\ai-portable\` 目录，不会改动 U 盘上原有的其他文件。制作 Ventoy 启动盘时，ISO 与引导文件不受影响。

## 盘内布局

```
ai-portable/
  opencode/  bin/opencode.exe
  claude/    bin/claude.exe
  codex/     vendor/x86_64-pc-windows-msvc/codex.exe
  pi/        node/node.exe + app/
  tools.json
  README.txt
```

每个工具目录内有对应的 `start-*.cmd`。脚本把该工具的配置、缓存、状态目录重定向到盘内，这是「不安装也能带状态」的关键：

| 工具 | 重定向变量 |
| --- | --- |
| OpenCode | `XDG_CONFIG_HOME` / `XDG_DATA_HOME` / `XDG_CACHE_HOME` / `XDG_STATE_HOME` |
| Claude Code | `CLAUDE_CONFIG_DIR` |
| Codex CLI | `CODEX_HOME` |
| pi | `PI_CODING_AGENT_DIR`（并附带 `node.exe` 运行时） |

在新机器上双击 `start-<工具>.cmd`，或在命令行里带参数运行（如 `start-codex.cmd --version`）验证可执行性。`tools.json` 记录本次写入的工具清单、体积与时间，便于事后核对盘内版本。

## 两个开关

**携带凭证**（默认开启）。开启后盘内有可用的 API Key 与登录态，插入即可用；代价是这些凭证以明文落盘，盘丢失等同于密钥泄露。关闭后 OpenCode 与 Claude Code 的密钥字段会被抹掉，Codex 与 pi 的 `auth.json` 不复制，到新机器需要重新登录。

**携带会话历史**（默认关闭）。开启后额外复制 OpenCode 的会话数据库与 Codex 的 `sessions/` 目录，用于在新机器上继续之前的对话。这两处体积增长快，且必须在工具退出后复制。

## 边界

- **只复制，不下载**：来源是本机已安装的原生可执行文件与包目录，找不到时面板提示先安装，不在写入过程中联网拉取。
- **MCP 服务器不随盘**：MCP 依赖本机的 uv / Python 虚拟环境，路径不可重定位。写入时会从 OpenCode 配置中移除 `mcp` 块并给出提示，避免在盘上留下指向不存在路径的配置。
- **凭证加密尚未实现**：当前便携目录是明文副本，产品愿景对凭证载体要求强制加密，该能力仍在补齐。过渡期建议只在可信任的私人 U 盘上开启携带凭证。
- **工具版本跟随本机**：盘内保存的是写入当时的版本，宿主升级后需要重新写入才能同步。

::: warning 旧版手工目录
早期手工搭建的 `F:\ai-portable\`（根级 `bin/`、`config/`、`data/`、`cache/`、`state/`）会被识别为旧布局并提示，但不会被自动删除或覆盖。确认不再使用后请自行清理。
:::

## 常见问题

**磁盘列表为空。** 确认 U 盘已插入且盘符可见。若为 USB 接入的移动硬盘仍未出现，用「重新检测」刷新。

**写入报空间不足。** 面板按当前勾选计算需求并预留余量。关闭「携带会话历史」或减少工具数量后重试。

**新机器上启动报错。** 先在命令行执行 `start-*.cmd --version`，确认是配置问题还是执行被拦截。Windows 可能对来自可移动介质的可执行文件提示安全警告。

实现链路与字段级细节见仓库[随身盘机制](https://github.com/Chelase/deploystrap/blob/master/.agent-rules/mechanisms/portable-usb.md)。
