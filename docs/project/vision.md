# 最终愿景

**让任何人在任何一台陌生机器上，用一个工具快速获得「带着自己上下文的 AI 开发环境」，并让 AgentOpenConnect（AOC）人人可一键安装、部署、接入。**

本页是面向使用者的愿景摘要；项目决策的最高依据是仓库的[产品最终愿景与最高规则](https://github.com/Chelase/deploystrap/blob/master/.agent-rules/rules/product-vision.md)。

## 主线一：AI 开发环境随身

换机器时，缺少的不只是可执行文件，还有个人配置、全局规则、prompts 和认证信息。

目标链路是：**环境检测 → 装齐 Agent 工具链 → 恢复加密个人档案 → 校验可用状态**。

已有的安装、扫描、压缩、加密与恢复能力将作为基础。当前 OpenClaw 归档并不等于完整的通用个人上下文档案。

## 主线二：AOC 安装与接入

AOC 面向多 Agent 协作，涉及中心节点、设备执行器和管理面板。安装器计划吸收 Python 环境、依赖、LLM 配置和证书分发的复杂度。

| 模式 | 预期体验 | 当前阶段 |
| --- | --- | --- |
| 本地体验 | 安装环境与依赖，配置模型，启动并检查健康状态 | 规划中 |
| 设备接入 | 导入包含中心地址与 mTLS 材料的加密胶囊，接入后验证 | 规划中 |
| 中心部署 | 通过 SSH 驱动 Linux 中心部署 | Phase 2，暂缓 |

当前版本尚未提供上述 AOC 功能。具体步骤见[开发路线](./roadmap)。

## 用真实场景衡量进展

阶段价值通过可验收场景判断。例如，在一台干净的 Windows 机器上，从零到 AOC 本地体验可用，计划目标为不超过 15 分钟。**这是待验证的验收目标，并非当前性能承诺。**

## 不变的约束

- 携带私钥与凭证的载体必须强制加密落盘。
- 安装失败要有镜像／安装包或手动引导，避免中间状态卡住用户。
- 只做 AOC 安装器与接入器，AOC 侧需求通过 issue 或文档提出。
- 完全无网、物理隔离的内网不属于目标场景。
- OpenClaw 迁移能力继续复用，新增投入围绕两条产品主线。
